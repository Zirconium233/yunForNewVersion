# V4 几何模板生成模式

此模式根据本地底图生成新点列，重新计算时间、累计距离、步数与配速；可选用已有记录的运动数据作为变化基线。它仍依赖底图定义跑道形状，**不是从零识别地图的路径规划器**。底图和参数不能证明实际运动发生，也不能保证服务端接受或成绩长期有效。此前记录被追溯取消的原因仍未确定。

## 离线生成与配置

仅生成文件，无须账号，也不会读取 `config.ini`：

```powershell
python tools/generate_route.py --config examples/routes/v4.json --output work_dir/route_preview.geojson
```

输出 GeoJSON 和同名 `route_preview.task.json`（逐点与汇总检查用，`ts=0` 是尚未运行的占位符）。输出文件已存在时会拒绝覆盖。可用支持 GeoJSON 的本地查看器预览，不要把调试文件放入 `tasks_*` 后通过旧打表入口运行。

`examples/routes/v4.json` 是路线配置模板。`base_geojson` 相对**路线配置文件所在目录**解析；命令行 `--route-config` 相对**启动命令时所在目录**解析。无需修改账号文件中的 `[Run]` 路线参数。

| 配置项 | 示例/默认 | 含义 |
|---|---|---|
| `base_geojson` | `base_v3.geojson` | 一条 LineString 的 FeatureCollection，点序为 `[经度, 纬度]` |
| `coordinate_system` | `GCJ-02` | 必须明确声明；不执行坐标转换。离线工具也支持 WGS84，当前主流程要求 GCJ-02 |
| `distance_m` | 2100 | 沿生成几何截取的目标长度，单位米；最终汇总使用时间采样后的实际几何长度 |
| `pace_min_km` | 6 | 名义配速，分钟/公里；6.5 表示 6 分 30 秒，不是 6 分 50 秒 |
| `cadence_spm` | 160 | 名义步频，步/分钟；累计步数按经过时间计算并取整 |
| `sample_seconds` | 1 | 时间采样间隔，整数 1～5 秒；最终点保留总时长余数 |
| `seed` | 20260919 | 固定种子可复现；填 `"auto"` 每次取新种子，实值写入输出 `metadata.seed` |
| `base_task` | 不设置 | 可以用已有 `tasklist_*.json` 的 `pointsList` 作几何底图；与 `base_geojson` 二选一 |
| `telemetry_task` | 不设置 | 已有记录中的逐点里程、时间和步数作为变化基线；设 `base_task` 且不填此项时默认使用同一文件 |
| `telemetry_variation` | 0.05 | 对样本分段距离、时间和步数做平滑的有界变化，0～0.15；总量重新归一。并非实测的人体行为模型 |
| `allowed_polygon_geojson` | 不设置 | 单环 GeoJSON Polygon；偏移上限 >5 米或启用绕行时必填，逐段检查是否在区域内 |
| `start_trim` / `end_trim` | 0 / 0 | 从底图头尾裁掉的点数；裁剪后至少 25 点 |
| `lane_change_indices` | `[90,175,290]` | 裁剪后点列中的偏移变更位置；超出当前点列的索引不触发 |
| `lane_change_choices_m` | `[-1.3,-0.9,0.9,1.2]` | 从中选择目标侧向偏移增量，单位米 |
| `lane_transition_points` | 12 | 每点向目标偏移靠近的比例为 1/此值；1 可复现原脚本的直接跳变 |
| `max_offset_m` | 5 | 侧向累计偏移限制，不含显式绕行距离；超出报错 |
| `detour_enabled` | false | 原 V4 的绕出并回归片段；默认关闭，不代表绕行区域可通行 |

开启绕行时还支持 `detour_index=220`、`detour_rejoin_offset=14`、`detour_exit_m=12`、`detour_forward_m=18`、`detour_step_m=3.5`。其中索引按偏移后的点列计算，非法索引会报错。默认未开启这些片段，不能凭此推断服务端判定效果。

需要以已有记录为基础时，复制模板配置，把 `base_geojson` 删掉，填写 `base_task` 指向该记录文件。例如文件在路线配置的同目录时填 `"base_task": "my_record.json"`，并将 `"seed"` 设为 `"auto"` 可逐次生成不同结果，实际种子保存在输出 JSON 的 `metadata.seed`，便于复查。路径仍按配置文件所在目录解析。保留运动样本时目标里程必须在样本实测里程 ±10% 内；跨度再大就不能声称保留原有速度特征。源数据必须有递增的逐点里程和时间、非回退的累计步数。样本采样过稀、重新投影造成几何长度损失超过 1% 时会报错，不会补造运动数据。

`allowed_polygon_geojson` 需要由使用者根据真实可通行范围提供，不能把简单的矩形外包框当作跑道边界。当前只支持一个无洞多边形；不支持多区域、跨过围栏的桥接，也不证明学校服务端围栏与该文件一致。

使用运动样本时，`pace_min_km`、`cadence_spm`、`sample_seconds` 不决定输出节奏，由样本的逐段数据决定；时间量化为整数秒时可能略微增加总时长。`max_offset_m` 只是偏移上限，单独调大不会主动增加偏移，实际变化由 `lane_change_indices`、`lane_change_choices_m` 和绕行参数控制。

示例底图来自用户提供的 V3 样本，位于约 `117.206,31.774` 的场地。GCJ-02 声明沿用其高德展示背景的假设，未做实地测量验证。**外校或其他场地必须更换底图、核对坐标系和可跑区域。** 本模块不查询学校围栏；现有协议中的 `isFence=Y` 等标志不是几何校验结果。

## 接入主流程

先用本地测试账号配置和本地 `getHomeRunInfo` fixture 进行假传输演练：

```powershell
python main.py --dry-run -f tests/fixtures/test_config.ini --dry-home examples/routes/dry_home.json --route-config examples/routes/v4.json
```

这条命令不联网、不登录、不等待真实跑步时长。fixture 仅用于演练，不代表学校实际要求。正式主流程入口为：

```powershell
python main.py -f config.ini --route-config examples/routes/v4.json
```

需要原有自动确认行为可加 `-a`。人脸源参数沿用原接口。`--route-config` 不能与 `-t` 或 `-d` 混用；不传该参数时保持旧模式。路线文件不会自动写回账号配置。

生成和几何输入校验在账号配置读取、登录和建记录之前完成。取得学校任务后、`start` 前检查里程、步频和坐标系。**要求踩点的任务（`raDislikes > 0`）暂不支持，会停止；不会虚构踩点列表。** 人脸准入、拒绝停止以及结束时的 `isStandard → 尾批 → finish` 链沿用现有实现。遇到任务下发的 `raSingleMileageMax` 会在到达上限时截断末点并进入结束链；这与 APK 的 `maxDistance` 分支相对应。不能把某校反馈的 2 km 写死为所有学校规则。

## 一致性与限制

- 源 V4 在默认裁剪和绕行下只有约 1878 米。新示例不裁剪、不绕行，目标 2100 米，实际长度约 2.096 公里；不得硬填成 2.100 公里。几何不足会报错，不缩放整座场地、不首尾瞬移拼接。如果学校最低要求 2 公里，应留出采样损失余量。
- 原源码的空间采样不均匀。新模式按时间重采样，逐段球面距离累加里程；采样长度损失超过目标的 1%（最低容差 1 米）时报错。底图相邻点最多 100 米，经纬度跨度最多 0.2 度。
- 点字段 `speed` 实际是配速 min/km，按 APK `SportRunMapActivity.java:4140` 的公式与 1～900 范围生成，保留两位小数；不能填米/秒。汇总里程以公里计，逐点里程以米计。
- 逐点等待，批次上传；网络和人脸处理延时纳入后续点时间和配速，不通过突发追赶上传消除延时。无运动样本时按恒定名义步频计算步数；有运动样本或使用打表入口时保留来源累计步数，等待期间不额外增加步数。实际总时长可能超过计划时长。
- 有运动样本时以其速度和步频的变化形状为基线，按生成路线长度重新计算速度及汇总；不同种子给出不同变化。自动种子的实值会保存供复现。此模式仍可能保留可识别的相似性，不代表规避服务端复审。
- 上传批次在服务端任务带 `passPointNum` 时按 APK 的规则确定：小于 10 回退 60，缓存点数严格超过阈值再发。任务未返回该字段时才用 `[Run] split_count` 兼容旧逻辑；不能把随机批量当成客户端行为。
- 修正原源码导入即依赖工作目录、缺少参数校验、偏移直接跳变、末点可能遗漏的问题。保留显式种子便于复现。生成模式不增加自动重试。
- 离线验证覆盖几何长度、时间/配速/步数一致性、原 V4 参数复现、网络延时、学校约束、生成失败不读取账号以及尾批结束链。它不能证明实机人脸通过、记录有效或不会追溯取消。
