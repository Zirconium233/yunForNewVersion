## 二、本轮人脸静态发现

下列 Java 路径均相对于 work_dir/src/sources/com/yunzhi/tiyu/。

### 1. 输入质量检查确实存在

JTFaceCompareActivity.java:532–602 的 K(DrawResult) 检查人脸框及五点姿态：框宽占预览宽度 40%–65%，框处于指定范围内，左右转向、俯仰和眼线倾斜受限；不是“任意照片编码就与客户端一致”。:978 附近调用人脸检测，再将坐标映射到预览区域后判定。

因此证件照并非总能满足取景约束。需要区分原图坐标、相机图像坐标和预览控件坐标；直接把照片宽高代入预览阈值不能宣称精确复现。后续需对照 DrawResult 的坐标变换及检测模型输出建立样本。

### 2. 注册照和跑中比对照的处理不同

- 注册：JTFaceAddActivity.java:281–304 读取 EXIF 旋转，按摄像头状态决定镜像，写 JPEG quality=100，然后 Luban.ignoreBy(100)；:343–346 提交 faceBaseData。
- 正常比对：JTFaceCompareActivity.java:634–655 旋转、按摄像头状态镜像、写 JPEG quality=100，再调用 FaceImageCompressor；:449–478 将最终文件字节编码为无换行 Base64。没有 data:image/jpeg;base64, 前缀。
- FaceImageCompressor.java:96–145：宽度超过 720 时，按比例缩到宽 720，写 JPEG quality=90；限制的是宽度，不是最长边。宽度不超过 720 则该步不重采样。
- :327–344：缩放结果大于 153600 字节才调用 Luban.ignoreBy(150)；Luban 后仍过大才进入二次质量压缩。
- 本轮通过 jadx 单类 --comments-level debug 重新导出缺失方法，得到 work_dir/face_review/FaceImageCompressor.java 的指令转储：依次尝试 quality 80、75、70、65、60、55、50、45、40、35、30、25、20，首个不大于 153600 字节的结果成功，否则失败。jadx 仍报告类型推断错误，因此这是低层指令证据，不是成功恢复的可编译 Java。
- 超时捕获分支 JTFaceCompareActivity.java:773 起另用 JPEG quality=90 + Luban.ignoreBy(100)，不能与正常比对共用一个硬编码压缩路径。

“Python JPEG 质量值相同”不代表 Android Bitmap 的输出字节相同。离线一致性应分别评价处理规则、图片解码内容和信封结构；只有复用相同编码器或传递同一最终文件，才能进一步要求字节一致。

### 3. 传输与成功判定

API.java:412–416：注册与比对是两个独立接口；比对体为 faceBaseData + recordId，提交 JSON，继续走通用加密拦截器。该人脸端点不在 RetrofitService 的分段 gzip 分支中；不能把上传体自动当作 multipart、视频文件或压缩点列处理。

JTFaceCompareActivity.java:298–328：先检查外层 code，再检查 data.status == "Y" 才回调比对成功。HTTP 200、业务 code 200、上传完成、人脸比对成功必须作为不同状态记录。注册的审核状态也不能由“请求成功”替代。

### 4. 调度及重试是专用状态机

SportRunMapActivity.java:785–789 读取 faceTime 和 randomList；:2990 起建立窗口。W1(:2854–2904) 用距离跨越判定触发：将窗口值与距离换算成米，判断落在前后距离区间内，并标记窗口已展示。faceTime 参与窗口倒计时，绝不是每隔 faceTime 秒上传一次。

窗口展示、采集、上传、比对、超时和结束是多个状态；:3339 起还能恢复未完成窗口。必须保留客户端的窗口标识和当前 recordId，不能仅在循环中添加一次 comparison 请求。

JTFaceCompareActivity.L(:606) 中有有限重试；Z(:696) 建立 30 秒等待状态；f(:347) 在指定条件下再次使用同一 B 文件提交。这里存在“同一次上传流程重用同一文件”的客户端证据，但不能推导为“跨核验窗口重放旧照一定通过”。重试应该作为人脸状态机内可测试的转移，不放进通用 HTTP 自动重试。具体间隔、退出条件和会话终止优先级均以调用链为准。

## 三、推荐实现方式

### 方案 1：单张照片输入适配器，作为最小离线基线

适用：先以用户本人照片验证输入到上传体的处理链。这里的“证件照”指人像照片，不需要包含证件号码的证件扫描件。

实现 photo source → 方向信息与预览坐标定义 → 人脸质量检查 → 对应分支图像处理 → Base64 → 请求构造 → 假服务器响应与状态处理。保留原图，以独立临时文件处理。照片源没有前置相机标志，不应无条件镜像；输入是否已镜像必须有明确约定。

优点：依赖少、可重复、容易逐层比较，推荐最先做。限制：替代了实时相机输入，只有处理、上传及状态逻辑可验收为一致；不能把文件来源或实时性也标记为一致。注册默认只查询状态，不自动替换底照。

### 方案 2：自拍视频抽帧，复用同一个上传管线

适用：单张照片质量不合格，或者希望从本人自拍视频中选取满足客户端取景规则的帧。

视频仅作为本地图片源，不直接上传 MP4。保留视频旋转元数据，确定性地抽取候选帧，经与方案 1 相同的检测和坐标映射筛选；记录所选帧的媒体时间与处理结果。优先取第一个符合标准的清晰帧，使离线测试可重复；没有合格帧则报输入不合格，不宣称通过。选择规则是新增输入适配行为，应与客户端原有行为分开标注。

优点：通常有更多可选图像。限制：不自动解决服务端活体或实时性要求，也不能把历史视频帧等同当前现场采集。不要加入原方案中没有客户端依据的随机噪声、亮度抖动、伪造 EXIF 或“去重防检测”处理，它们会使一致性验收失去基准。

### 方案 3：Android 图像处理参照程序 / 当前相机辅助输入

适用：严格要求 Android 图像处理一致，或需要后续对照真实相机行为。

建立独立的本地 Android 测试入口，复现 Bitmap、EXIF、Luban 的处理路径，把处理后的图片与元数据作为 Python 管线的参照输入；不需要修改官方 APK 或注入它的相机。参照程序可以使用固定本地图片验证编码，也可以用当前相机采集进行人工辅助测试。若最终采用人工官方 App 完成核验，必须验证它与脚本的登录会话是否互斥，不能默认两端共享 token 无影响。

优点：最适合作为编码和旋转/镜像的差分基准。成本最高，Android 依赖和设备测试单独算；完整官方 App 采集状态仍不能仅靠一个压缩 helper 宣称已复现。

推荐顺序：先修 A 阶段三个 P1，再做方案 1 的离线实现与状态机，方案 2 作为 source 插件，方案 3 用于严格图像一致性对照。无需同时实现三套上传流程。

## 四、验收标准：明确“哪些层一致”

| 层次 | 必须验收的内容 | 不应混淆的结论 |
|---|---|---|
| 输入适配 | 照片损坏、无脸、多人/选脸策略、方向与镜像、视频无合格帧；确定性选择 | 文件输入与实时相机采集不同，记录这一差异 |
| 取景质量 | 五点、框位置、预览坐标转换；阈值边界前后各有 fixture；零分母、无检测结果明确失败 | 不以“图片里有人脸”替代客户端姿态门 |
| 图片处理 | 注册/普通比对/超时分支分别测试；宽度 719/720/721、大小阈值两侧、压缩失败 | Pillow 与 Android 字节不同不等于逻辑错误，但也不等于字节一致 |
| 编码传输 | 最终图片字节无换行 Base64；正确键集和 recordId；JSON→SM4 信封；UUID/sign 上下文；本人脸接口不额外 gzip | 假传输返回成功不证明信封正确，必须解开请求进行断言 |
| 结果处理 | code=200/status=Y；code=200/status=N；空 data；HTTP 错误；解码失败；超时；会话终止后的迟到回调 | 仅 status=Y 才是模拟响应中的比对通过 |
| 调度 | 距离越界与边界、不重复触发、窗口中断、未完成窗口恢复、faceTime 下界、并发防重、等待及重试退出 | 不用固定时间循环替代距离窗口 |
| 集成 | 登录后 profile 生效；runFaceStatus 开关与状态查询分离；canSport=N 中止；recordId 持续一致 | 不能因新增人脸模块绕过已有业务拒绝 |
| 无账号模式 | 所有网络入口禁用或 mock，虚拟时钟，无真实睡眠，无账号/底照写回；日志仅留脱敏结果和元数据 | 输出名称使用 offline_client_compatibility，而非 face_passed_live |

验收产物：字段/状态证据矩阵、可复现 fixture 清单、脱敏的请求解包结果、测试报告。每项标记“静态已确认 / Python 已验证 / Android 差分已验证 / 服务端未验证”。要达到完整客户端行为一致，还需补齐检测坐标、Luban 实际算法、超时与重试全部分支，不能只实现普通照片 POST 就验收完成。
